# Launch Plan

Distribution alone does not create awareness. StayLoaded's launch is organized around proof, trust, discoverability, and repeated release communication.

## Positioning

Name: **StayLoaded**

Tagline: **Log off. Stay loaded.**

Primary promise: keep farms working without leaving a gaming PC connected overnight.

Differentiator: the player's own server-side stand-in replaces the disconnected client; this is not just a chunk-loader block or decorative NPC.

Trust promise: data safety is tested and documented per Minecraft version, and unsupported server builds fail closed.

## Pre-Launch

- Reserve consistent `StayLoaded` slugs where platforms allow it.
- Use an original icon and visual identity that cannot be confused with Unplugged AFK.
- Publish a 30-45 second demonstration: active farm, `/stayloaded`, client disconnect, farm continues, client returns with state intact.
- Publish the compatibility matrix and known limitations before downloads open.
- Recruit 10-20 technically competent server owners for a closed beta.
- Prepare reproducible test worlds for mob farms, crop farms, redstone, portals, death, and restart recovery.

## Marketplace Pages

Publish the same release on:

- Modrinth for discovery and update delivery
- Hangar for the Paper-focused audience
- CurseForge for broader search reach
- GitHub Releases as the source-of-truth archive

Each page should lead with the demo, support matrix, safety warning, three-step installation, command example, and source link. Descriptions and artwork must be original rather than copied from the inspiration project.

Target search terms naturally in copy: `Paper fake player`, `AFK bot`, `offline farms`, `server-side player`, `keep farms loaded`, and supported Minecraft versions.

## Launch Sequence

1. Announce the closed beta with a short proof video and a narrowly scoped tester application.
2. Publish a GitHub pre-release and collect structured reports with diagnostics.
3. Ship the public beta simultaneously on Modrinth, Hangar, and CurseForge.
4. Post a technical launch article explaining why a true player stand-in differs from chunk tickets and NPCs.
5. Share only in communities whose rules permit project promotion: Paper forums/Discord channels, technical Minecraft communities, relevant subreddits, and server-owner communities.
6. Send concise release notes for every compatibility or safety improvement.

## Sustainable Growth

- Add an opt-in update notification for administrators, never players.
- Publish verified compatibility badges per Minecraft version rather than claiming broad compatibility.
- Turn support questions into searchable troubleshooting pages.
- Maintain a public roadmap and label beginner-friendly issues for contributors.
- Ask beta users for concrete testimonials only after stable operation.
- Track marketplace views-to-downloads, first-run success, retained servers, crash-free sessions, and support volume.
- Prioritize the version lines with real active-server demand instead of maximizing a nominal version count.

## Release Gate

Do not market StayLoaded as production-ready until automated and manual tests cover reconnect, inventory, death, dimensions, restart, and recovery on both supported versions. A missed launch date costs less than a player's lost inventory.
